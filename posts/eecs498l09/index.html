Lecture 9：Hardware and Software

这一讲很实用：神经网络最终要在真实硬件和软件栈上运行，模型结构、张量布局、自动微分和设备并行会共同决定训练速度。

1. CPU、GPU 与 TPU

CPU 核心较少，但单核强、缓存大、适合控制流和串行任务；GPU 拥有大量较简单的核心，擅长把独立的矩阵元素并行计算；TPU 则为矩阵乘法和混合精度设计了专用阵列。

当单卡放不下模型或数据时，可以把多个 GPU 放到同一台服务器上；更大的训练还需要跨服务器通信。

GPU 快并不代表任何程序放上去都会快。只有当计算量足够大、并行工作足够规则时，才能摊薄 kernel launch 和 CPU-GPU 数据传输开销。小张量、频繁 Python 循环、不断在 CPU 与 GPU 之间复制数据，都可能让加速器处于等待状态。

训练瓶颈也不总是算力。若算子需要读取大量内存、只做少量计算，它可能受 memory bandwidth 限制；矩阵乘法计算密度高，更容易接近峰值 FLOPs。判断性能问题时，应区分 compute-bound、memory-bound、input pipeline 和 communication-bound。

2. 深度学习框架的职责

框架至少需要提供三件事：张量运算、自动微分和神经网络模块。PyTorch 的 Tensor 类似 NumPy 数组，但可以放在 GPU 上；requires_grad 让操作记录到计算图；nn.Module 管理层和可学习参数；optim 实现 SGD、Adam 等更新。

DataLoader 则负责数据集的索引、打乱、多进程加载和 batch 组装。

一个典型训练 step 实际包含多层工作：

  1. CPU 从磁盘读取并预处理样本；
  2. DataLoader 组装 batch，并尽量提前准备下一批；
  3. batch 传到 GPU；
  4. 前向传播构建激活和损失；
  5. autograd 反向计算梯度；
  6. optimizer 更新参数并清空旧梯度。

只优化第 4 步而忽略数据加载或传输，端到端吞吐量未必会提升。PyTorch 梯度默认会累加，因此通常还要在每个 step 显式调用 zero_grad；需要 gradient accumulation 时，才有意跨多个 mini-batch 保留梯度。

3. 动态图与静态图

PyTorch 默认采用动态计算图：执行 Python 代码时即时构建图，图结构可以依赖输入，因此调试和处理可变长度序列很自然。

静态图先描述网络，再编译或优化后执行。它便于做算子融合、跨设备调度和序列化部署，但代码和执行图之间的距离更大。

两者的取舍可以概括为：动态图库于灵活、易调试；静态图利于编译优化、部署和跨语言运行。现代框架通常同时提供两种模式。

算子融合的意义是减少中间张量写回显存和再次读取。例如 Conv、BatchNorm、ReLU 分开执行会产生多个 kernel 和中间结果，融合后可在一次更大的 kernel 中完成。静态图更容易提前看到整段计算并做这类全局变换；动态图则需要 tracing、JIT 或编译器捕获执行图。

序列化也体现了区别：静态图通常可以把结构和权重一起保存，在没有原始 Python 程序的环境中部署；纯动态图保存的往往主要是 state dict，加载时仍需由代码重新构造模型。生产部署因此比课堂里的 model(x) 多出模型导出、版本兼容和运行时约束。

4. 本讲总结

硬件决定哪些计算便宜，框架决定如何表达这些计算。训练效率瓶颈可能来自 FLOPs、显存、内存带宽、数据加载或设备间通信，不能只看模型参数量。
