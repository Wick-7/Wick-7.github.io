Lecture 8：CNN Architectures

卷积、池化和归一化只是零件，真正的性能来自如何安排深度、宽度、下采样和残差路径。这一讲按时间线比较了几种影响最大的 CNN 架构。

1. 从 AlexNet 到 VGG

AlexNet 证明了大规模数据、GPU 和 ReLU 卷积网络可以在 ImageNet 上取得突破。它由卷积层、池化层和全连接层组成，但各层的尺寸和连接方式还比较不规则。

VGG 的贡献是把设计规则化：大量使用 $3\times3$ 卷积、$2\times2$ max pooling，并通过堆叠小卷积增加深度。

代价是参数量、显存和 FLOPs 很大。VGG 的经验是“更深通常更强”，但也暴露出单纯加深网络的训练和效率问题。

比较架构时不能只数层数。至少要同时看：

  • Parameters：决定模型权重占用和一定程度的过拟合风险；
  • FLOPs：近似描述一次前向计算量，但不等同于真实延迟；
  • Activation memory：训练时还要保存中间特征，常比权重更占显存；
  • 规则性与并行度：同样 FLOPs 的网络，硬件利用率可能差很多。

例如 VGG 的大部分参数集中在末端全连接层，而前面的高分辨率卷积贡献了大量计算。GoogLeNet 和 ResNet 的改进不仅是提高准确率，也是在重新分配参数和计算。

2. GoogLeNet：把效率放进结构

GoogLeNet 通过 aggressive stem、$1\times1$ bottleneck 和 global average pooling 减少计算。Inception 模块并行使用 $1\times1$、$3\times3$、$5\times5$ 卷积以及 pooling，再把结果拼接起来。

它还在中间层加入 auxiliary classifier，帮助梯度传到网络前部。这个技巧在 BatchNorm 出现前尤其有用。

$1\times1$ 卷积在 Inception 中不是“观察一个像素”那么简单：它在每个空间位置对全部通道做线性组合，因此能改变通道数并学习跨通道交互。先用它压缩通道，再做昂贵的 $3\times3$ 或 $5\times5$ 卷积，可以显著降低 FLOPs。

Global average pooling 则把每个通道的整张特征图平均成一个数，替代巨大的全连接层。这样参数更少，空间位置与通道语义之间的对应也更直接。

3. ResNet：让网络学残差

当网络很深时，直接学习映射 $H(x)$ 很难；ResNet 改为学习残差 $F(x)$，再通过 shortcut 输出：

$$ y=F(x)+x. $$

恒等路径让梯度可以跨层传播，也让网络更容易学习“保持输入不变”这样的简单变换。Bottleneck block 用 $1\times1$ 卷积先降维、再做 $3\times3$ 卷积、最后升维，以较低 FLOPs 支撑更深网络。

Residual learning 解决的是 degradation problem：更深的普通网络即使理论上能复制浅网络并额外添加恒等层，训练误差也可能反而更高。残差参数化把“新增层先学成恒等映射”变得容易，因为只需令 $F(x)\approx0$。因此 ResNet 的突破主要是优化条件改善，而不是简单增加了一条信息通道。

当输入输出通道数或空间尺寸不同，shortcut 不能直接相加，需要用 stride 或 $1\times1$ projection 对齐维度。相加要求形状完全一致，这一点是实现 residual block 时最容易出错的地方。

预激活 ResNet 把 BatchNorm 和 ReLU 放在卷积之前，使 shortcut 更接近真正的恒等映射。

4. ResNeXt、MobileNet 与自动设计

ResNeXt 在 bottleneck 中使用 grouped convolution，让多个分组路径并行提取特征，在保持计算量相近的情况下增加 cardinality。

MobileNet 面向移动设备，使用 depthwise separable convolution：先对每个通道分别做空间卷积，再用 $1\times1$ pointwise convolution 混合通道，显著降低计算量。

Neural Architecture Search 则把架构设计也交给控制器和验证反馈自动搜索。

这些后续结构分别探索了不同的“扩展轴”：ResNeXt 增加分组路径数量，Squeeze-and-Excitation 显式重标定通道，DenseNet 让每层读取之前所有层以复用特征，MobileNet 分解空间和通道计算。它们共同说明：网络容量不只有 depth 和 width 两个旋钮，连接方式和算子分解同样重要。

5. 本讲总结

架构演化的主线不是简单堆层数，而是不断回答三个问题：怎样让梯度稳定地穿过深度、怎样用更少计算获得更强表示、怎样让设计更容易扩展。实践中应根据显存、延迟和数据规模选择架构，而不是只追求最大模型。
