《Stanford CS336 Spring 2026 Lecture 5：GPUs, TPUs, and FlashAttention》课堂笔记

发表于2026-07-31|更新于2026-07-31|学习笔记
|浏览量:

这节课进入 CS336 的系统部分。目标不是记住 CUDA 的每个 API，而是建立一套能解释性能的心智模型：GPU 为什么会慢，以及怎样重新组织计算和数据，让它快起来。

全课可以压缩成一句话：

现代加速器的矩阵乘法能力增长得比内存带宽快得多，所以高性能机器学习的核心往往不是少算几个 FLOP，而是少搬数据、连续搬数据，并让搬进片上存储的数据被尽可能多地复用。

课程分为三部分：

  1. GPU 的硬件、执行和内存模型，以及它与 CPU、TPU 的关系；
  2. Roofline 模型与六类 GPU 优化方法；
  3. 用 tiling、fusion、online softmax 和 recomputation 重新推导 FlashAttention。

开场：为什么语言模型需要 GPU？

语言模型的能力会随计算量增加而以相当稳定的方式提升。更快的硬件、更好的利用率和更多芯片，即使不改变模型算法，也能推动性能继续增长。

早期处理器主要依靠 Dennard scaling：晶体管变小后，提高时钟频率，在大致相同的功耗密度下让串行指令越来越快。这个趋势在 2000 年代逐渐失效。晶体管数量仍在增加，但频率和单线程性能不能再按原来的速度增长，于是扩展计算的主要方式变成了并行：

$$ \text{更快的单个执行单元} \quad\longrightarrow\quad \text{大量执行单元同时工作}. $$

过去十年 GPU 可提供的浮点算力增长超过三个数量级。这里不只有晶体管数量的贡献，还包括：

  • 更多并行执行单元；
  • 专门执行矩阵乘法的 Tensor Core；
  • BF16、FP8、INT8 等低精度数据格式；
  • 稀疏性以及更高效的数据通路。

因此，LLM scaling 和 GPU scaling 实际上紧密绑定。模型设计也不能完全脱离硬件：一个数学上 FLOPs 更少的结构，真实运行时未必更快。

Part 1：GPUs in depth - how they work and important parts

1. CPU、GPU 与 TPU 的核心差异

1.1 CPU 优化延迟，GPU 优化吞吐

CPU 只有相对少量但很强的核心，拥有复杂的控制逻辑、大缓存、分支预测和乱序执行。它希望让一个线程尽快完成，适合复杂控制流和低延迟任务。

GPU 则把更多晶体管用于大量较简单的计算单元，减少对复杂分支和大缓存的投入。它希望让单位时间内处理的数据总量最大，适合规则、可并行的数值计算。

这带来一个基本 trade-off：

硬件 优化目标 擅长 不擅长
CPU 单任务延迟 分支、控制、串行依赖、通用程序 数量巨大的规则并行运算
GPU 总吞吐 矩阵运算、向量运算、相同程序处理大量数据 复杂分支、细粒度同步、小而不规则的任务
TPU 机器学习吞吐 大规模矩阵乘法和规则 tensor program GPU 式细粒度、通用的 SIMT 编程

1.2 GPU 的计算组织：SM、block、warp、thread

GPU 包含多个 SM（Streaming Multiprocessor）。可以把每个 SM 看成一个能独立接收任务的计算簇，其中有普通算术单元、矩阵乘法单元、寄存器、调度器和 shared memory。

CUDA 的工作层级可以写成：

$$ \text{grid} \supset \text{block} \supset \text{warp} \supset \text{thread}. $$

  • thread：执行 kernel 的一个逻辑实例，不同 thread 处理不同数据；
  • warp：NVIDIA GPU 中 32 个连续编号的 thread，硬件按 warp 发射指令；
  • block：一组 thread，被调度到某个 SM 上，并共享该 block 的 shared memory；
  • grid：一次 kernel launch 产生的全部 block。

GPU 采用 SIMT（Single Instruction, Multiple Threads）：同一 warp 中的 thread 在同一时刻执行同一条指令，但操作不同的数据。thread 本身很轻量；当一个 warp 等待内存时，调度器可以切换到另一个已经就绪的 warp，用并发隐藏延迟。

需要注意：block 与 SM 不是永久的一一绑定。一个 SM 可以先后执行许多 block，也可能同时驻留多个 block，具体数量受寄存器、shared memory 和硬件上限约束。

1.3 GPU 的内存层级

离执行单元越近的存储越快、越小、也越昂贵：

层级 作用域 特点
Register 单个 thread 最快、容量很小，过量使用会降低可并发的 warp 数
Shared memory / L1 单个 block / SM 片上 SRAM，快且可由程序显式管理
L2 cache 整张 GPU 片上共享缓存
Global memory / HBM 整张 GPU 容量大、带宽高，但延迟远高于片上 SRAM

同一 block 内的 thread 可以经 shared memory 交换数据。不同 block 若要通信，通常必须经过 global memory 或拆成多个 kernel，因为 block 的执行顺序一般没有保证。

课件给出的数量级直觉是：SRAM 面积成本可比 DRAM 高约 $100\times$，但访问速度约快 $8\times$。因此不可能简单地把全部 HBM 换成 shared memory。高性能 kernel 要做的是：只把当前需要的一小块数据搬入片上存储，并充分复用。

1.4 TPU 与 GPU：结构趋同，粒度不同

GPU 与 TPU 在高层结构上非常相似，都包含：

  • 轻量控制单元；
  • 专门的矩阵乘法电路；
  • 较快的片上存储；
  • 大容量的外部高带宽内存。

二者的主要差异在粒度。GPU 有较多 SM 和较多、较小的矩阵乘法单元，因此更灵活，非矩阵操作也更容易映射。TPU 通常用较少但更大的 Tensor Core，每个 core 内的 MXU（Matrix Multiply Unit） 负责大块矩阵乘法，编程模型更规则，没有完全对应 CUDA warp 的层级。

术语尤其容易混淆：

  • NVIDIA 的 Tensor Core 指 SM 内的矩阵乘法单元；
  • TPU 的 TensorCore 指一个较完整的处理核心，其中的矩阵单元叫 MXU。

二者底层矩阵乘法电路都可采用 systolic array。后续并行课程还会看到，更大的区别来自芯片之间怎样互连，而不只是单芯片内部如何计算。

2. 为什么矩阵乘法在 GPU 上很特别？

早期 GPU 没有专用矩阵乘法硬件，研究者借用 programmable shader 实现通用数值计算。V100 时代开始加入 Tensor Core 后，矩阵乘法成为硬件中特殊的一等公民：低精度矩阵乘法吞吐可以比普通标量浮点操作高一个数量级以上。

这会改变算法设计的成本模型：

“一个矩阵乘法 + 若干逐元素操作”的时间，可能主要不是由矩阵乘法决定，而是由那些需要反复读写 HBM 的逐元素操作决定。

与此同时，峰值 FLOP/s 的增长快于 HBM 带宽。计算单元越来越多，但把数据及时送到这些单元越来越难，这就是 memory wall。

Part 1 recap

  • GPU 以大量并行 thread 和 SIMT 执行模型换取吞吐；
  • block 在 SM 上执行，warp 是硬件发射和分支分歧的基本单位；
  • register、shared memory、cache 和 HBM 构成速度递减、容量递增的内存层级；
  • Tensor Core 让矩阵乘法变得特殊，也让数据搬运成为主要瓶颈。

Part 2：Understanding GPU performance

1. Roofline：先判断瓶颈在哪里

定义算术强度（arithmetic intensity）：

$$ I=\frac{\text{FLOPs}}{\text{从目标内存层级搬运的 bytes}}. $$

设硬件峰值计算吞吐为 $P_{\max}$，内存带宽为 $B$，则可达到的吞吐上界是：

$$ P\leq \min\left(P_{\max},\; B I\right). $$

等价地，一个操作的时间至少为：

$$ T\geq \max\left(\frac{F}{P_{\max}},\;\frac{M}{B}\right), $$

其中 $F$ 是 FLOPs，$M$ 是搬运的字节数。

  • 当 $I<P_{\max}/B$ 时，程序位于斜线段，是 memory-bound；
  • 当 $I\geq P_{\max}/B$ 时，程序到达平台，是 compute-bound；
  • 转折点 $I^*=P_{\max}/B$ 也叫 ridge point。

优化的第一步不是盲目减少 FLOPs，而是判断瓶颈：

  • memory-bound：减少 HBM 访问、增加数据复用、融合操作、降低精度；
  • compute-bound：减少 FLOPs，或使用更快的矩阵/低精度硬件；
  • 工作量太小：增加并行度或 batch，摊薄 launch 和调度开销。

课件用 ReLU 举例时写了 $8$ bytes/FLOP（FP32）和 $4$ bytes/FLOP（FP16）。这其实是算术强度的倒数。按标准定义，若把比较记作一个 operation：

$$ I_{\mathrm{FP32}}=\frac{1}{8}\ \mathrm{op/byte}, \qquad I_{\mathrm{FP16}}=\frac{1}{4}\ \mathrm{op/byte}. $$

精度减半后，同样带宽能送入两倍元素，所以算术强度翻倍。

2. 让 GPU 变快的六种方法

课程列出的六种方法不是彼此独立的零散技巧。除 control divergence 外，它们几乎都在回答同一个问题：如何缓解数据搬运瓶颈？

方法 直接解决的问题 核心代价或限制
Control divergence warp 内不同 thread 走不同分支 需要改写控制流，未必总能避免
Low precision 每个元素占用的带宽和存储过多 数值范围、精度与量化开销
Operator fusion 中间结果反复写回、读出 HBM kernel 更复杂，寄存器压力可能上升
Recomputation 保存和读取 activation 太贵 增加 FLOPs
Memory coalescing warp 的访存分散成许多事务 受 layout、stride、alignment 约束
Tiling 同一数据从 HBM 被重复读取 tile 选择复杂，受片上容量和 shape 影响

2.1 Control divergence：warp 会串行执行分支

假设一个 warp 中部分 thread 走 if，另一部分走 else。由于同一 warp 一次只能发射一条共同指令，硬件通常会：

  1. 执行 if 分支，屏蔽走 else 的 thread；
  2. 再执行 else 分支，屏蔽走 if 的 thread；
  3. 在分支汇合后恢复共同执行。

所以两个分支都可能被执行，只是不同 thread 在不同阶段处于空闲状态。最坏情况下，有效吞吐接近各分支时间之和。

分支本身并非绝对禁止。真正需要避免的是同一 warp 内的分歧。如果整个 warp 都走同一分支，影响会小得多。规则的 mask、predication 或 branchless 表达有时更适合 GPU，但也不应为了消灭一个很便宜的分支而增加大量无用计算。

2.2 Low precision：少搬 bit，也让专用硬件算得更快

低精度有两个收益：

  1. 相同数量的元素需要更少内存和带宽；
  2. Tensor Core 对 BF16、FP16、FP8 等格式提供更高计算吞吐。

训练通常采用 mixed precision，不是把每一步都粗暴地改成低精度。例如矩阵乘法的输入可用 BF16/FP8，乘积的部分和用 FP32 累加；softmax、归一化、loss 或优化器状态可能保留更高精度。

格式越低，选择越不统一：

  • BF16：8 位 exponent、7 位 mantissa，范围接近 FP32，训练中常用；
  • FP8 E4M3：更多 mantissa，精度较好但动态范围较小；
  • FP8 E5M2：更多 exponent，动态范围较大但精度更低；
  • MXFP8：以小 block 共享 scale，改善单一全局 scale 无法适应局部幅值的问题；
  • MXFP4：进一步压缩到 4 bit，但可表示值极少，对 scaling 和训练稳定性要求更高。

课上以 Blackwell 的 MXFP8 为例：每 32 个元素共享一个 E8M0 scale，数据本身可用 E4M3。细粒度 scale 提高了有效精度，却让转置变复杂，因为转置后的 32 元素分组发生了变化。实际训练可能同时维护正常布局和转置布局的量化副本。

这说明低精度不是免费的：需要计算 scale、量化和反量化，也可能保留多个副本。FP8 matmul 理论峰值即使约为 BF16 的两倍，端到端训练也不会自动获得 $2\times$ 加速。真正困难的是决定哪些 tensor、哪些层、哪些操作可以降低到哪一种精度。

2.3 Operator fusion：让中间结果留在片上

考虑：

$$ y=\sin^2(x)+\cos^2(x). $$

朴素 eager 执行可能启动 5 个 kernel：sin、平方、cos、平方、加法。每个 kernel 都可能从 HBM 读输入、把中间结果写回 HBM，再被下一个 kernel 读入。

融合后，一个 kernel 只读取一次 $x$，在寄存器或 shared memory 中完成全部计算，最后只写一次 $y$。

融合同时减少：

  • 中间 tensor 的 HBM 流量；
  • 临时 tensor 占用的显存；
  • kernel launch 的固定开销。

简单 pointwise fusion 可由 torch.compile、XLA 等编译器自动完成。复杂 fusion 仍可能需要 Triton/CUDA kernel。融合也不是越多越好：过大的 kernel 会增加寄存器和 shared memory 压力，降低 occupancy，甚至造成 register spill，必须以 profiling 结果为准。

2.4 Recomputation：用便宜计算换昂贵内存

反向传播通常保存前向 activation，反向时读取它们来计算梯度。但对 sigmoid、ReLU 等低算术强度操作，保存和读取 activation 可能比重新计算更贵。

课上的三个连续 sigmoid 示例中：

  • 保存每一层中间值，需要 8 次内存读写；
  • 丢弃中间值、反向时重算，降为 5 次必要读写，即原来的 $5/8$；
  • 代价是多做几次 sigmoid。

这就是 activation checkpointing 背后的系统逻辑。它不只是“显存不够时的妥协”：当计算单元富余而 HBM 是瓶颈时，主动丢掉结果再计算，可能同时节省显存并提高速度。

是否值得重算取决于操作：矩阵乘法很贵，盲目重算可能拖慢程序；简单逐元素操作或巨大中间矩阵则更适合重算。

2.5 Memory coalescing：让一个 warp 的地址落在连续 burst 中

DRAM 不是逐字节独立读取。一次访问会激活一段 row，并以 burst 形式返回一块连续数据。如果一个 warp 的 32 个 thread 同时访问相邻地址，硬件可以把这些请求合并为少量 memory transaction，这叫 coalesced access。

关键是比较同一条指令、同一时刻、不同 thread 的地址，而不是看单个 thread 随时间是否连续。例如对 row-major 矩阵：

  • thread $t$ 访问 A[row, col + t]：相邻 thread 访问相邻列，通常可合并；
  • thread $t$ 访问 A[row + t, col]：相邻 thread 的地址相差一整行，形成大 stride，通常不能合并。

即使每个 thread 自己沿一行顺序扫描，如果不同 thread 同时位于不同的行，warp 级访问仍可能是不连续的。这也是阅读 CUDA 索引时最容易混淆的地方。

Layout、stride、vectorization 和 alignment 都会影响合并效果。矩阵维度若让每一行起点错开 burst 或 tile 边界，一个 tile 可能需要额外 transaction。此时给维度做 padding，虽然增加了少量 FLOPs，却可能显著加快运行。

2.6 Tiling：把 HBM 流量变成片上复用

考虑方阵乘法：

$$ C=AB, \qquad C_{ij}=\sum_{k=1}^{N}A_{ik}B_{kj}. $$

朴素实现会从 global memory 反复读取同一个 $A_{ik}$ 和 $B_{kj}$。Tiling 把 $A$、$B$、$C$ 分成边长约为 $T$ 的小块：

  1. 协作地把 $A$ 和 $B$ 的当前 tile 搬入 shared memory；
  2. 在片上计算该 tile 对 $C$ 的部分和；
  3. 沿归约维度换入下一对 tile；
  4. 完成后把 $C$ tile 写回 HBM。

按课件的简化分析：

  • 未 tiled 时，每个输入元素约从 global memory 读取 $N$ 次；
  • tile size 为 $T$ 时，每个输入约从 global memory 读取 $N/T$ 次；
  • 因而 global memory 访问减少约 $T$ 倍。

Tiling 同时带来两类收益：复用发生在 shared memory，搬入时还可以让 thread 协作形成 coalesced access。

但 tile 越大并不一定越好。tile size 要同时满足：

  • 能装进 SM 的 shared memory 和 register；
  • 保留足够多的 resident block / warp 来隐藏延迟；
  • 与矩阵维度和内存布局对齐；
  • 避免大量边界 thread 只做 padding；
  • 适配 Tensor Core 所要求的矩阵 fragment 形状。

所以高性能库会为不同 shape 准备多个 kernel，编译器的 autotune 则会实际 benchmark 多种 tile 配置。矩阵维度取 8、16、32 的倍数不是数字崇拜，而是为了匹配硬件的 transaction、vector width 和 tensor-core tile。

3. 为什么矩阵只增大一维，速度会突然下降？

课程开头展示了一张反直觉的曲线：方阵维度整体越大，吞吐通常越高，但曲线中夹杂着离散的分层和周期性断崖。

现在可以逐层解释：

  1. 总体上升：小矩阵工作量不足，算术强度和并行度较低；矩阵变大后逐渐填满计算单元，接近 Roofline 平台。
  2. 同一尺寸附近出现多层曲线：维度能否被 2、8、16、32 等整除，会影响 tile 边界、vectorized load 和 memory alignment。对齐好的 shape 更容易得到 coalesced access。
  3. 周期性骤降：tile 数量越过 SM 数量的整数波次，产生 wave quantization。

课上的 A100 例子使用 $256\times128$ tile：

$$ 1792:\quad \frac{1792}{256}\times\frac{1792}{128} =7\times14=98\ \text{tiles}, $$

而维度增加到 1793 后需要向上取整：

$$ 1793:\quad \left\lceil\frac{1793}{256}\right\rceil \times \left\lceil\frac{1793}{128}\right\rceil =8\times15=120\ \text{tiles}. $$

A100 有 108 个 SM。98 个 tile 可以在一波中完成；120 个 tile 需要第二波，但第二波只有 12 个 tile，绝大多数 SM 都空闲。矩阵仅增大一维，却因为调度粒度从一波变成两波而显著变慢。

这也解释了为什么给 vocabulary、hidden size 或 batch 维度做少量 padding，有时反而会加速。多算一点并不可怕；让昂贵硬件等待才可怕。

Part 2 recap

  • Roofline 用算术强度判断程序位于 memory-bound 还是 compute-bound 区域；
  • coalescing 和 fusion 减少不必要的 HBM 事务；
  • tiling 把数据搬到 shared memory 后反复复用；
  • low precision 与 recomputation 分别用精度和额外计算换内存；
  • shape、alignment 和 wave quantization 解释了矩阵性能曲线中的锯齿与断崖。

Part 3：Putting it together - unpacking FlashAttention

1. FlashAttention：把所有原则放到一个 kernel 中

单个 attention head 的标准计算是：

$$ S=\frac{QK^\top}{\sqrt d}, \qquad P=\operatorname{softmax}(S), \qquad O=PV. $$

如果序列长度为 $N$，$S$ 和 $P$ 都是 $N\times N$。朴素实现会：

  1. 计算 $S$，写回 HBM；
  2. 从 HBM 读取 $S$ 做 softmax，把 $P$ 写回 HBM；
  3. 再从 HBM 读取 $P$ 与 $V$ 相乘。

问题不只是 $\mathcal{O}(N^2d)$ FLOPs，而是 materialize 并反复搬运两个 $\mathcal{O}(N^2)$ 中间矩阵。FlashAttention 是 exact attention：它不改变数学结果，也不把二次 FLOPs 变成线性；它通过 IO-aware 的计算顺序，避免把完整 $S$、$P$ 写到 HBM。

1.1 第一步：对 $Q$、$K$、$V$ 做 tiling

把 $Q$ 按行切成 $Q_i$，把 $K,V$ 切成 $K_j,V_j$。每次只在 SRAM 中计算一个 score tile：

$$ S_{ij}=\frac{Q_iK_j^\top}{\sqrt d}. $$

矩阵乘法本身很容易 tiled，真正的问题是 softmax。softmax 的分母依赖整行所有 key，似乎必须先看到完整的 $S$。

1.2 第二步：用 online softmax 合并分块结果

对某个 query row，假设已经处理了前几个 key block，并维护：

  • $m$：目前见过的 score 最大值；
  • $\ell$：以 $m$ 为基准的指数和；
  • $\widetilde O$：尚未除以归一化分母的加权 value 和。

处理新的 score block $S_j$ 和 value block $V_j$ 时，逐行更新：

$$ m_{\mathrm{new}} =\max\left(m,\operatorname{rowmax}(S_j)\right), $$

$$ P_j=\exp\left(S_j-m_{\mathrm{new}}\right), $$

$$ \ell_{\mathrm{new}} =e^{m-m_{\mathrm{new}}}\ell +\operatorname{rowsum}(P_j), $$

$$ \widetilde O_{\mathrm{new}} =e^{m-m_{\mathrm{new}}}\widetilde O +P_jV_j. $$

所有 key block 处理完后：

$$ O=\frac{\widetilde O}{\ell}. $$

其中除法按 row broadcast。若新 block 出现更大的最大值，因子 $e^{m-m_{\mathrm{new}}}$ 会把旧的指数和与旧输出重新缩放到新的基准下。因此，这个递推和一次性计算稳定 softmax 完全等价。

1.3 第三步：融合、片上复用与反向重算

对每个 tile，FlashAttention 在一个融合 kernel 内完成：

  1. 从 HBM 载入 $Q_i,K_j,V_j$；
  2. 在 SRAM 中计算 $S_{ij}$；
  3. 应用 causal mask、缩放、指数等操作；
  4. 更新 online softmax 的 $m,\ell,\widetilde O$；
  5. 直接把概率 tile 与 $V_j$ 相乘，不把 $S_{ij}$ 或 $P_{ij}$ 写回 HBM；
  6. 最后只写出 $O$ 以及反向传播所需的少量统计量。

反向传播同样不保存完整的 $N\times N$ attention matrix，而是根据 $Q,K,V,O$ 和 softmax 统计量逐 tile 重算 score 与 probability。这正是 recomputation：增加一些便宜且高吞吐的矩阵计算，换掉巨大的 activation 存储和 HBM 流量。

因此，FlashAttention 同时使用了本课几乎全部核心思想：

原则 在 FlashAttention 中的体现
Tiling 分块读取 $Q,K,V$，在 SRAM 中计算 score 和 output tile
Fusion matmul、mask、scale、exp、归一化与 value 聚合尽量在一个 kernel 内完成
Recomputation backward 重新生成 score/probability，不保存完整 $N\times N$ activation
Coalescing 以适合硬件的 layout 和 block shape 读取连续数据
Low precision matmul 可使用 BF16/FP16/FP8，关键归约保留足够精度
Control regularity 规则 tile 与 mask 让 warp 以结构化方式执行

FlashAttention 的关键结论是：

渐近 FLOPs 相同，不代表算法一样快。只改变计算顺序和存储位置，就可能得到数量级可观的端到端收益。

2. 把六种方法统一成一张图

课程最后将优化方法归纳为三类资源交换：

2.1 减少必须发生的内存访问

  • coalescing：让分散请求合并为更少的 DRAM transaction；
  • fusion：让中间结果不离开片上存储。

2.2 让一次搬入的数据多用几次

  • tiling：把工作集搬入 shared memory/register，完成一批计算后再换下一块。

2.3 用其他资源换内存

  • low precision：用数值精度换带宽、容量和 Tensor Core 吞吐；
  • recomputation：用额外 FLOPs 换 activation 读写与存储；
  • control regularity：用规则的数据和控制布局换有效并行度。

它们共同提高的是“每个昂贵 byte 所完成的有效工作”，最终目标是越过 Roofline 的 ridge point，让矩阵单元持续忙碌。

3. 实际优化时的检查顺序

面对一个慢的 ML workload，可以按下面的顺序排查：

  1. 先测量：看 kernel time、HBM bandwidth、Tensor Core 利用率、occupancy 和 launch 数，不凭 FLOPs 猜性能。
  2. 判断瓶颈：用 arithmetic intensity 和 Roofline 区分 memory-bound、compute-bound 或 launch-bound。
  3. 检查 shape：矩阵是否足够大，维度是否适配 Tensor Core、vector width 和 tile；padding 后是否更快。
  4. 检查 layout：warp 的同一条 load/store 是否访问连续地址，transpose 是否导致 stride access。
  5. 减少中间 tensor：尝试 compiler fusion 或 fused library kernel。
  6. 提高复用：如果在写自定义 kernel，选择合适 tiling，把热数据留在 register/shared memory。
  7. 选择精度：优先使用成熟 mixed-precision 路径，验证 loss、overflow 和端到端速度。
  8. 考虑重算：对 activation 巨大而计算便宜的部分做 checkpointing 或 fused recomputation。
  9. 最后再手写 kernel：先用 cuBLAS、cuDNN、FlashAttention、PyTorch compile 等成熟实现，再针对 profiler 证明的热点下手。

全课总结：本节课最重要的结论

  1. GPU 是吞吐机器，不是更快的 CPU。 它用大量轻量 thread 和规则的 SIMT 执行换取并行吞吐。
  2. block、warp 和 thread 是理解 CUDA 的基本层级。 性能问题经常来自 warp 内分支、block 调度和资源占用。
  3. 必须尊重内存层级。 HBM 容量大但昂贵，register/shared memory 小而快；好 kernel 会显式管理数据在哪里。
  4. Roofline 是第一诊断工具。 $P\leq\min(P_{\max},BI)$ 说明性能由计算峰值和带宽共同限制。
  5. 矩阵维度会改变真实性能。 alignment、tile divisibility 和 SM wave 都会让相邻 shape 的速度差很多。
  6. 低精度、fusion、recomputation、coalescing、tiling 本质上都在优化有效数据移动。
  7. FlashAttention 是 IO-aware algorithm。 它以 online softmax 解开全局归一化依赖，再用 tiling、fusion 和 recomputation 避免 materialize 二次大小的中间矩阵。
  8. 硬件意识会反过来影响模型架构。 在当前加速器上，规则的大矩阵乘法和少量数据移动通常比理论 FLOPs 更值得优先考虑。
